1. **Effective directory.** The push walk keeps an effective directory, starting at the payload's cwd, and updates it per segment: `cd <dir>` and `pushd <dir>` set it (through `dash_c_directory`, so `~` and relative paths resolve against the current effective directory); `cd` alone and `cd ~` set it to the home directory; `popd` restores the directory pushed last. A `cd`, `pushd` or `popd` the walk cannot resolve (`cd -`, a `$` or backtick in the argument, flags, more than one argument, `popd` with nothing pushed) makes the effective directory unknown, and a `git push` in an unknown directory with no explicit refspec, or with `HEAD`, is denied by name ("the checkout it pushes from cannot be determined"), like an unparseable push (B-08). A `(` saves the state and the matching `)` restores it, so a `cd` inside a subshell does not reach the segments after it. A `git -C <dir>` still overrides, resolved against the effective directory.
